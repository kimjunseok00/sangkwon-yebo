# 받을 데이터 목록 (주초현, 11/23~24)

출처: 서울열린데이터광장(data.seoul.go.kr) → 검색 "서울시 상권분석서비스" → 각 데이터의 "파일 내려받기"(CSV).
받은 파일은 `data/raw/`에 두고 저장소에는 올리지 않는다.

## 받을 파일

| 우선 | 데이터 이름 | 쓰는 곳 | 저장 이름 예 |
|---|---|---|---|
| 필수 | 서울시 상권분석서비스(점포-상권) | 점포 수, 개업·폐업 점포 수, 프랜차이즈 점포 수 → 정답과 핵심 특징 | `store_2019.csv` … `store_2025.csv` |
| 필수 | 서울시 상권분석서비스(영역-상권) | 상권 이름, 종류, 좌표 → 지도 | `area.csv` |
| 권장 | 서울시 상권분석서비스(추정매출-상권) | 점포당 매출 증감 특징 | `sales_2019.csv` … |
| 선택 | 서울시 상권분석서비스(상권변화지표-상권) | 서울시가 매기는 상권 변화 분류. 비교 자료 | `change.csv` |
| 선택 | 서울시 상권분석서비스(길단위인구-상권) | 유동인구 특징 | `footfall.csv` |

연도별로 파일이 나뉘어 있으면 2019년부터 최신까지 전부 받는다.

## 받자마자 확인할 것 (11/24까지, 결과를 이슈 #1에 댓글로)

1. 열 이름: `python -m ingest.seoul --inspect data/raw/store_2024.csv`
   - `ingest/seoul.py`의 `COLUMN_MAP_STORE`와 다르면 실제 이름을 댓글로 남긴다(팀장이 고침).
   - 특히 `개업_점포_수`, `폐업_점포_수`가 **상권 단위 파일에도 있는지**. 없으면 즉시 팀장에게 알린다(계획 전체에 영향).
2. 기간: 가장 이른 분기와 가장 늦은 분기. 2019년 1분기 ~ 2025년 4분기가 다 있어야 한다.
3. 외식업 업종 이름 10개가 무엇으로 적혀 있는지(`서비스_업종_코드_명`).
4. 인코딩: UTF-8인지 CP949인지(읽기 함수가 둘 다 처리하지만 기록해 둔다).
5. 영역-상권 파일의 좌표 열 이름과 좌표계(EPSG 번호). 데이터 설명 페이지에 적혀 있다.
6. 이용 조건(공공누리 유형). 발표·서비스에 써도 되는지 확인.

# 전국판 데이터 (#18, 팀장 11/24~11/27)

| 우선 | 데이터 이름 | 받는 곳 | 저장 이름 |
|---|---|---|---|
| 필수 | 행정안전부 지방행정 인허가 데이터: 식품_일반음식점 (전체 파일) | LOCALDATA 파일 다운로드(file.localdata.go.kr) 또는 공공데이터포털 '행정안전부_식품_일반음식점' | `localdata_food.csv` |
| 선택 | 식품_휴게음식점 (커피·제과 업종용) | 같은 곳 | `localdata_cafe.csv` |

- 좌표계는 Bessel 중부원점TM(EPSG:5174, 공공데이터포털 설명 기준). 전국판은 시군구 단위라 좌표 변환 없이도 계산된다. 지도는 시군구 중심점으로.
- 공공데이터포털 메타데이터로 확인된 열: `개방자치단체코드`, `업태구분명`, `인허가일자`, `상세영업상태명`, `소재지전체주소`, `도로명전체주소`.
- 확인된 열: `폐업일자`, `영업상태명`. 11/23 공공데이터포털 파일로 확인 완료(주소는 `지번주소`·`도로명주소`).
- 업태 값(`업태구분명`)은 `--inspect`의 빈도표를 보고 `INDUSTRY_MAP`을 고친다. 서울판 업종과 비교할 수 있는 것만 `SEOUL_CROSSWALK`에 넣는다.
- 이용 조건(공공누리 유형): 서울판·전국판 모두 **상업적 이용 가능 여부**를 기록한다. 금융기관에 API를 판다는 사업 모델의 전제다(#23).
