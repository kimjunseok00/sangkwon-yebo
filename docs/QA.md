# 예상 질문 답변표 (#25)

발표·질의응답·교수님 의견용. 각 질문마다 **말할 문장**(발표자가 그대로 말해도 되는 한두 문장), **근거**(숫자와 문서 위치), **피할 말**을 둔다.
⏳ 표시는 아직 결과가 없어 나중에 채울 칸이다. 숫자는 `docs/EXPERIMENTS.md`가 원본이며, 바뀌면 여기도 같이 고친다.

마지막 갱신: 2026-11-23 (전국판 첫 성적표 기준, 서울판·C3 전)

---

## A. 맞느냐, 믿을 수 있느냐

### A1. 그래서 맞아요? 실제 데이터랑 비교하면 정답이에요?
- **말할 문장**: "정답이라고 하지 않습니다. 결과가 이미 나온 과거 3년을, 그 이전 데이터만으로 예측해서 실제와 맞춰 봤고 그 성적을 그대로 공개합니다. 2024년 말에 위험 상위 10%로 찍은 곳 중 58%가 실제로 다음 해 폐업률 상위였습니다. 아무렇게나 고르면 25%입니다."
- **근거**: 전국판 상위 10% 적중률 53% / 57% / 58% (2022~2024년 기준, 무작위 약 25%). `docs/EXPERIMENTS.md` 전국판 첫 성적표. 서울판 ⏳(11/26).
- **피할 말**: "정확도 58%", "58% 확률로 망한다". 적중률은 '상위 10% 경고 중 실제 위험 칸 비율'이지 개별 가게 확률이 아니다.

### A2. 결과 보고 기준을 맞춘 거 아니에요?
- **말할 문장**: "기준은 실험 전에 문서에 적고 커밋해 두었습니다. 결과를 본 뒤 바꾼 것이 딱 하나 있는데, 그것도 수정 전 값과 함께 공개했습니다."
- **근거**
  - 판정 기준(AUC 이득 0.02, 3년 중 2년)은 11/23 결과 전에 `docs/EXPERIMENTS.md`와 `core/config.py`에 기록. 깃 커밋 기록으로 시점 확인 가능.
  - 결과 본 뒤 바꾼 것: 전국판 업종 표에 '기타' 업종 추가. 수정 전 데이터 손실 13.9%(기준 10% 불통과) → 수정 후 0.17%. 판정 기준은 그대로. '기준 변경 기록'에 "결과를 보기 전인가: 아니오"로 공개.
  - 모델 조정은 2022·2023년만 보고 한다. 2024년은 최종 확인용.
- **피할 말**: "한 번도 안 바꿨다". 바꾼 게 있으므로 먼저 말하는 게 낫다.

### A3. AUC 0.68이면 낮은 거 아니에요?
- **말할 문장**: "높다고 하지 않습니다. 폐업은 사장님 개인 사정, 임대료처럼 공공데이터에 없는 이유가 많아서 원래 맞히기 어렵습니다. 저희가 보여드리는 건 '단순한 규칙보다 3년 연속 나았다'는 것입니다."
- **근거**: 전국판 모델 AUC 0.666 / 0.671 / 0.685 vs 나은 기준선 0.643 / 0.627 / 0.652. 이득 +0.022 / +0.044 / +0.033. 2022년은 기준(0.02)을 겨우 넘음.
- **피할 말**: "AI가 정확하게 예측한다", "높은 정확도".

### A4. 기준선이 일부러 약한 거 아니에요?
- **말할 문장**: "기준선 중 하나는 서울시 창업위험도의 폐업률 계산 방식을 따라 한 것입니다. 가상 데이터로 미리 돌려 봤을 때 저희 모델이 이 기준선을 못 이겼을 만큼 약하지 않습니다."
- **근거**: 기준선 2개(작년 폐업률, 3년 평균 폐업률, 업종 내 비교). 가상 데이터 사전 점검에서 모델 불통과. `docs/EXPERIMENTS.md` 사전 점검.

### A5. 개별 가게가 망할지도 맞혀요?
- **말할 문장**: "못 합니다. 동네와 업종 단위로 '다음 해 폐업이 몰릴 위험이 같은 업종 중 높은 편인가'를 보여주는 참고 정보입니다. 화면과 API 응답마다 이 문구가 붙어 있습니다."
- **근거**: 정답 정의 = 다음 해 폐업률이 같은 업종 칸 중 상위 25%. 모든 API 응답에 `caution` 문구 포함(`api/main.py`).

### A6. 전국 데이터는 믿을 만해요?
- **말할 문장**: "세 가지를 미리 정해 확인했습니다. 옛 폐업 기록이 남아 있는지, 버리는 데이터가 얼마인지, 그리고 서울에서 이 데이터로 계산한 폐업률이 서울시 공식 통계와 같은 방향으로 움직이는지입니다."
- **근거**: C1 통과(폐업 기록 가장 적은 2020년도 2024년의 83%), C2 통과(손실 0.17%), C3 ⏳(서울 교차 순위 상관, 11/26~27). 원본 231만 건 중 230만 건 사용.

### A7. 코로나(2020~2021) 같은 특이한 해는요?
- **말할 문장**: "시험은 2022~2024년 예측으로 봤고, 코로나 시기는 학습에만 들어갑니다. 큰 충격이 오는 해에는 과거 패턴이 덜 맞을 수 있다는 한계로 밝힙니다."
- **근거**: 시험 연도 2022·2023·2024(`core/config.py`). 연도별 성적을 따로 공개하므로 특정 해에 약하면 보인다.

## B. 서비스와 경쟁

### B1. 서울시가 이미 해 주지 않아요?
- **말할 문장**: "서울시 창업위험도는 서울만, 지난 기록 요약입니다. 저희는 전국을 다루고, 다음 해를 예측하고, 그 예측이 과거에 얼마나 맞았는지 성적을 공개합니다."
- **근거**: 서울시 창업위험도(과거 요약, 서울), 서울시 AI 자가진단(이미 장사 중인 사장님용), 서울신보 AI 예측(계획 단계). 오픈업 프로(유료, 연 990만~5,000만 원)도 예측 성적은 공개하지 않는 것으로 확인(우리가 찾아본 범위).
- **피할 말**: "아무도 안 하는 것". 서울신보가 비슷한 걸 준비 중이므로 "성적 공개"와 "전국"을 차별점으로 말한다.

### B2. 돈은 누가 내요?
- **말할 문장**: "소상공인 대출을 하는 금융기관입니다. 대출 심사 시스템이 저희 API를 불러 지역·업종 위험을 참고합니다. 호출 기록이 남아 사용량대로 받을 수 있습니다."
- **근거**: 금융기관용 API(`/v1/risk`), 호출 기록(`logs/api_calls.jsonl`, 키별 집계 #22). 가격은 가설 단계(⏳ 교수님 의견 후 정리).
- **피할 말**: 지자체·신용보증재단에 판다는 말(중간발표 지적 사항). 구체적 매출 숫자를 근거 없이 말하지 않는다.

### B3. 은행이 직접 만들면 되지 않아요?
- **말할 문장**: "큰 은행은 만들 수 있습니다. 저희가 보는 곳은 분석 조직이 따로 없는 지역 금융기관입니다. 이들이 원하는 건 데이터가 아니라 검증된 점수인데, 저희는 그 점수의 과거 성적까지 같이 드립니다."
- **근거**: 전국 231만 건을 정리하고 매년 다시 검증하는 비용. 성적표 공개(`/v1/scorecard`), 자동 갱신(#24).
- **주의**: 지역 금융기관 수요는 **가설**이다. 인터뷰로 확인하지 않았다고 솔직히 말한다(외부 의견 #13으로 보완).

### B4. 공공데이터로 돈 벌어도 돼요?
- **말할 문장**: "두 데이터 모두 이용허락범위가 '제한 없음'이라 상업적으로 써도 됩니다. 출처는 화면과 API 문서에 표시합니다."
- **근거**: 공공데이터포털 '행정안전부_식품_일반음식점', 서울열린데이터광장 '서울시 상권분석서비스' 모두 이용허락범위 제한 없음(11/23 확인, `docs/DATA_SOURCES.md`).

### B5. 시군구 단위면 너무 넓지 않아요?
- **말할 문장**: "맞습니다. 전국판은 시군구 단위가 한계입니다. 그래서 서울판은 골목 상권 단위로 만들어 같은 방법이 좁은 단위에서도 통하는지 보여드립니다. 인허가 데이터에 주소가 있어 동 단위로 좁히는 게 다음 단계입니다."
- **근거**: 전국판 2,504칸(관리 자치단체 × 업종), 서울판 상권 단위 ⏳.

### B6. 2026년 예측인데, 이미 지나간 해 아니에요?
- **말할 문장**: "공공데이터는 한 해가 다 끝나야 연간 통계가 됩니다. 지금은 2025년 데이터로 2026년을 예측한 상태이고, 2026년 4분기가 쌓이면 자동 갱신으로 2027년 예측으로 바뀝니다."
- **근거**: 진행 중인 해는 분기가 다 차지 않아 자동 제외(`features/build.py`). 자동 갱신(#24), 공공데이터포털 API 일간 갱신.

### B7. 폐업이 많으면 무조건 나쁜 상권이에요?
- **말할 문장**: "아닙니다. 가게가 자주 바뀌는 활발한 상권도 폐업률이 높습니다. 그래서 개업률과 점포 수 변화를 같이 보고, 화면에는 '위험이 높은 편'이라고만 표시합니다."
- **근거**: 특징에 개업률(open_rate), 점포 수 증감(store_growth) 포함(`core/schemas.py`). 화면 문구 규칙(`AGENTS.md`).

## C. 기술

### C1. 그냥 엑셀로 하면 되는 거 아니에요? 소프트웨어 기술이 뭐예요?
- **말할 문장**: "네 가지를 보여드리겠습니다. 미래 정보가 섞이지 않게 하는 시험 구조, 전국 231만 건을 몇 초에 처리하는 데이터 변환, 금융기관이 직접 부르는 API, 그리고 코드를 올릴 때마다 자동으로 도는 테스트입니다."
- **근거**
  - 누설 방지: 예측 연도 T는 T-1년까지만 학습(`experiments/backtest.py`, 테스트로 강제)
  - 데이터 변환: 100만 건 약 7초, 서울판과 같은 형식으로 바꿔 같은 코드 재사용(`ingest/localdata.py`)
  - API: 키 인증, 호출 기록, 자동 문서(`/docs`) 시연
  - CI: PR마다 테스트 33개 자동 실행. 깨진 PR이 막히는 화면 캡처(#23)
- **발표 장면**: 흐름도 한 장 + API 실시간 호출 + Actions 빨간 X 캡처.

### C2. AI(LLM)는 어디에 써요?
- **말할 문장**: "위험 점수 계산에는 LLM을 쓰지 않습니다. 숫자는 통계 모델이 계산하고, LLM은 이미 계산된 숫자를 쉬운 말로 설명하는 데만 씁니다."
- **근거**: `AGENTS.md` 규칙 5. Gemini 설명은 추가목표(#8).
- **피할 말**: "AI가 예측한다". 예측은 머신러닝 모델(그래디언트 부스팅)이 한다.

### C3. 모델이 기준선을 못 이기면요? (서울판 판정이 불통과일 때)
- **말할 문장**: "그 경우도 미리 정해 두었습니다. '예측 도구'가 아니라 '비교·설명 도구'로 주장을 낮추고, 못 이긴 성적표도 그대로 보여드립니다."
- **근거**: `docs/EXPERIMENTS.md` 통과 판정 규칙. 성적표 화면은 숨기지 않는다(`AGENTS.md`).
